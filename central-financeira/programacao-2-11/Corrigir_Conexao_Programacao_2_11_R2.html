O que a avaliação encontrou

Foram analisados os três arquivos recebidos: o guia HTML R1, as instruções TXT e o Manifest de referência. O Código.gs completo não fazia parte do material. Por isso, os itens abaixo tratam do mecanismo de correção, do verificador e da publicação. Os cálculos, as fórmulas e a planilha não foram avaliados.

Lógica Integração

  • A causa real não é um nome isolado. O gerador não confere se cada função chamada foi declarada. O R1 corrigia só um nome. O R2 confere todas as chamadas a funções privadas (nome_) e todas as chamadas google.script.run.
  • Sem o _, a função-base ficava pública. Qualquer página com acesso ao /exec podia chamá-la por google.script.run, e ela aparecia no menu Executar. A correção também fecha essa exposição de dados.
  • O verificarProgramacaoFinanceira não percorria as funções-base. O R2 traz um verificador de integração opcional, que só faz leitura.

Funcionamento Ferramenta

  • Uma menção ao nome num comentário bloqueava o R1 por engano. O R2 ignora comentários, textos e expressões regulares ao contar referências.
  • O R1 aceitava um único arquivo. Se a função estivesse em outro .gs, ele dava um falso “ausente”. O R2 aceita os demais arquivos do projeto, só para consulta.
  • O R1 exigia a chamada exata (month, scope) e ignorava referências sem parênteses, como callbacks. O R2 verifica o vínculo, e não a grafia dos parâmetros.
  • O R1 não verificava funções declaradas duas vezes em arquivos diferentes. Nesse caso, a última declaração substitui a anterior sem aviso.
  • O botão de baixar podia falhar em navegadores mais antigos, porque o link não era inserido na página.

Design Guia

  • O HTML tinha 4 passos e o TXT, 7, para o mesmo procedimento. Os dois agora seguem a mesma numeração, de 1 a 6.
  • Os trechos de código não tinham botão de copiar. Foi incluído um em cada trecho, para evitar erro de digitação.
  • Foram acrescentados modo escuro, foco visível no teclado e uma lista de conferência para cada passo, salva apenas na memória da página.
  • O resultado aparecia como um texto único. Agora o diagnóstico vem numa lista, com a gravidade e a linha de cada item.

Manifest

O R1 não tinha o bloco webapp, embora o guia publique em /exec. O R2 o inclui com o acesso restrito a você. Os escopos OAuth continuam sendo detectados automaticamente: veja Manifest antes de fixá-los.

Verificador de integração (opcional)

É o que faltou na verificação anterior. Ao ser executado no editor, ele percorre todas as funções do projeto, em todos os arquivos. Depois lista cada chamada a uma função privada (nome_) que não existe e sugere o nome parecido, quando houver.

Ele só faz leitura: não abre a planilha, não grava dados, não muda permissões e não cria acionadores. Para instalar, crie o arquivo Arquivos → + → Script com o nome VerificadorIntegracao e cole o conteúdo nele. Não cole no final do Código.gs.

/** Central Financeira · verificador de integração R2 (somente leitura). */
function verificarIntegracaoFinanceira() {
  const g = globalThis;
  const nomes = Object.getOwnPropertyNames(g).filter(function (n) {
    try { return typeof g[n] === 'function'; } catch (e) { return false; }
  });
  const existe = new Set(nomes);
  const faltando = {};
  let analisadas = 0;
  nomes.forEach(function (fn) {
    let src;
    try { src = Function.prototype.toString.call(g[fn]); } catch (e) { return; }
    if (/\{\s*\[native code\]\s*\}\s*$/.test(src)) return;
    analisadas++;
    const locais = new Set();
    src.replace(/\bfunction\s+([A-Za-z_$][\w$]*)/g, function (_, n) { locais.add(n); });
    src.replace(/\b(?:const|let|var)\s+([A-Za-z_$][\w$]*)/g, function (_, n) { locais.add(n); });
    const re = /(^|[^.\w$])([A-Za-z_$][\w$]*_)\s*\(/g;
    let m;
    while ((m = re.exec(src))) {
      const n = m[2];
      if (existe.has(n) || locais.has(n)) continue;
      (faltando[n] = faltando[n] || []).indexOf(fn) < 0 && faltando[n].push(fn);
    }
  });
  const problemas = Object.keys(faltando).sort().map(function (n) {
    const semSufixo = n.replace(/_+$/, '');
    return {
      chamada: n,
      usadaEm: faltando[n],
      sugestao: existe.has(semSufixo) ? 'Renomeie a declaração "' + semSufixo + '" para "' + n + '".' : 'Declaração não encontrada.'
    };
  });
  const ok = analisadas > 0 && problemas.length === 0;
  const resultado = {
    tipo: 'INTEGRACAO_FINANCEIRO',
    ok: ok,
    funcoesAnalisadas: analisadas,
    problemas: problemas,
    aviso: analisadas === 0 ? 'Nenhuma função foi listada; o verificador não pôde avaliar o projeto.' : undefined
  };
  console.log(JSON.stringify(resultado, null, 2));
  return resultado;
}

Resultado esperado: INTEGRACAO_FINANCEIRO com ok: true. Se o texto de uma string HTML contiver algo como nome_(, ele pode aparecer como aviso: confira antes de alterar qualquer coisa. Se funcoesAnalisadas for 0, o ambiente não permitiu listar as funções, e o resultado não vale como aprovação.

Escopo e limites

A ferramenta foi testada localmente com códigos fictícios: o erro original, um comentário que cita o nome antigo, uma função declarada em outro arquivo, uma declaração duplicada e uma chamada google.script.run para uma função privada. A sua cópia instalada não foi acessada, e nenhuma planilha foi lida ou gravada.

A análise é estática e conservadora. Ela só corrige sozinha um tipo de caso: a chamada termina em _, existe uma única declaração com o mesmo nome sem o _, e esse nome antigo não aparece em nenhum outro lugar do código. Os demais casos aparecem no diagnóstico e bloqueiam a geração do código. Esta correção não resolve um ReadTimeout independente nem valida o OCR real.

Se o ReadTimeout voltar a aparecer, os pontos a revisar no Código.gs são estes:

  • ler cada aba uma vez, com getValues() em bloco, em vez de ler célula por célula dentro de laços;
  • guardar o snapshot do mês em CacheService por alguns minutos;
  • usar LockService nas gravações.

Estas são orientações gerais. Elas só podem ser confirmadas com o código completo.
