CENTRAL FINANCEIRA — CORREÇÃO DA CONEXÃO DA PROGRAMAÇÃO 2.11
Revisão do guia: P211-CONEXAO-R4 • 04/11/2026 • substitui a R1, a R2 e a R3

ERRO IDENTIFICADO
ReferenceError: p211Base_getInteressesSnapshot_ is not defined
O gerador da Programação 2.11 declarou a função p211Base_getInteressesSnapshot
sem o sublinhado final, mas o código chama p211Base_getInteressesSnapshot_.
O erro veio do gerador, não dos dados que você preencheu. A correção é
acrescentar um _ na declaração. Ela não muda lançamentos, impostos,
permissões, fórmulas, cálculos, telas nem o Manifest, e não ativa acionadores.

JÁ APLICOU A CORREÇÃO DA R1, DA R2 OU DA R3?
Siga os passos mesmo assim. O passo 2 mostra como reconhecer uma correção já
feita e como conferir se ficou algum ponto com o nome antigo. Se a lista de
arquivos do projeto tiver um VerificadorIntegracao (criado pela R2 ou pela
R3), apague-o antes de publicar: menu de três pontos ao lado do nome > Excluir.

CORREÇÃO MANUAL NO EDITOR (CAMINHO PRINCIPAL)
Aplique a correção no código que já está instalado; não reinstale a
programação. Os passos são os mesmos do HTML.

1. Guarde uma cópia de segurança no computador.
   No editor do Apps Script, abra o Código.gs e clique em qualquer linha do
   código. Aperte Ctrl+A e depois Ctrl+C (no Mac, ⌘A e ⌘C). Abra o Bloco de
   Notas (no Mac, o TextEdit, e escolha Formatar > Converter em Texto Simples),
   cole com Ctrl+V (⌘V) e salve no computador como Codigo_backup.txt, com a
   codificação UTF-8. Confira se o arquivo termina com a última linha do
   código. O botão Salvar do editor não faz esta cópia: ele só grava o projeto
   na sua conta. Não crie a cópia como outro arquivo dentro do projeto.

2. Procure o nome em todos os arquivos e só depois acrescente o sublinhado (_).
   Clique em qualquer linha do código (o cursor deve piscar dentro dele) e
   aperte Ctrl+F (no Mac, ⌘F). Uma caixa de busca aparece no alto, à direita
   da área de código. Se abrir a busca do navegador, feche-a, clique dentro do
   código e tente de novo. Procure o nome da linha abaixo, sem o parêntese.
   Copie só o nome, sem espaços e sem a quebra de linha (não use três cliques:
   dê dois cliques no nome ou arraste o mouse só sobre ele), ou digite-o:

p211Base_getInteressesSnapshot

   Use as setas da caixa de busca para passar por todos os resultados,
   primeiro no Código.gs e depois em cada arquivo .gs e .html do projeto
   (lista de arquivos, à esquerda). POR ENQUANTO, SÓ OLHE: NÃO ALTERE NADA.
   Em cada resultado, veja o que vem logo depois do nome:
   a) "function p211Base_getInteressesSnapshot(" — é a declaração que precisa
      do sublinhado. Anote em que arquivo ela está; o sublinhado é digitado no
      fim deste passo.
   b) "function p211Base_getInteressesSnapshot_(" — a correção já foi feita
      (por exemplo, pela R1). Não acrescente outro _. Confira os outros
      resultados: com a declaração já corrigida, um ponto de código num .gs
      que ainda use o nome SEM _ (uma chamada, typeof, globalThis. ou o nome
      passado como valor) está quebrado e também recebe o _, no fim deste
      passo. Se o nome estiver sozinho entre chaves, como
      "{ p211Base_getInteressesSnapshot }", escreva
      "p211Base_getInteressesSnapshot: p211Base_getInteressesSnapshot_".
      Se ele aparecer entre aspas, num .html ou depois de
      "google.script.run.", pare.
   c) "p211Base_getInteressesSnapshot_(" em outro ponto — é a chamada correta.
      Não altere.
   d) Com a declaração ainda SEM _: o nome sem _ em qualquer outro ponto de
      código (seguido de ")", "," ou ".", numa chamada, sozinho entre aspas,
      ou depois de "google.script.run.") — PARE. Não altere nada e veja
      "ATENÇÃO: QUANDO PARAR", abaixo.
   e) O nome dentro de um comentário (depois de // ou entre /* e */) ou no
      meio de uma frase de mensagem (por exemplo, em console.log, Logger.log
      ou num texto de erro), sem "(" logo depois — não impede a correção. Não
      precisa mudar.
   Depois abra a página Acionadores (ícone de relógio, na barra à esquerda) e
   confira se a coluna Função mostra o nome sem o _. Se mostrar, pare.
   AGORA, SÓ SE NENHUM RESULTADO MANDOU PARAR: volte ao Editor (ícone < >, na
   barra à esquerda) e abra o arquivo da declaração. Clique logo antes do
   parêntese de "function p211Base_getInteressesSnapshot(" e digite o
   sublinhado (_). Deve ficar "function p211Base_getInteressesSnapshot_(".
   Não mude mais nada nessa linha nem no resto do código. Se a declaração já
   tinha o _, acrescente-o só nos pontos de código indicados no item b.
   Se você já tinha digitado o _ e algum resultado mandou parar, desfaça com
   Ctrl+Z (no Mac, ⌘Z) até a linha voltar a ser o que era. Se já tinha
   salvado, salve de novo depois de desfazer.
   Se a busca não achar nada no Código.gs, confira se o cursor está dentro do
   código e se só o nome foi copiado, sem espaços nem quebra de linha (na
   caixa de busca, o nome deve ocupar uma linha só; apague o que estiver
   depois dele). Se ainda assim não achar, procure nos outros arquivos .gs. Se
   não achar em nenhum, pare.

3. Salve e rode o verificador principal.
   Se você estiver em outra página (como Acionadores), volte ao Editor (ícone
   < >, na barra à esquerda) e abra o Código.gs. Salve o projeto com Ctrl+S
   (no Mac, ⌘S) ou pelo ícone de disquete. Na lista de funções ao lado do
   botão Executar, escolha verificarSistemaFinanceiro e clique em Executar. Se
   ela não aparecer na lista, abra o arquivo .gs onde ela está. O resultado
   aparece no Registro de execução, abaixo do código. Procure
   VERIFICACAO_FINANCEIRO com ok: true. Esse verificador percorre
   getNavigationSnapshot, o caminho onde o erro apareceu.

4. Rode o verificador da programação.
   Do mesmo jeito, execute verificarProgramacaoFinanceira e procure
   PROGRAMACAO_FINANCEIRA com ok: true e programacao: "2.11". Não execute
   FIN_PROGRAMACAO_MENSAL pelo editor. Se quiser uma conferência extra, use o
   verificador opcional (abaixo) agora e apague o arquivo dele antes de
   publicar (passo 5).

5. Publique uma nova versão na implantação que você já usa.
   Antes, confira a lista de arquivos: se houver um VerificadorIntegracao,
   apague-o (menu de três pontos ao lado do nome > Excluir). Depois clique em
   Implantar > Gerenciar implantações. Não use "Nova implantação": ela cria
   outro endereço. Na lista à esquerda, clique em cada implantação
   ativa até achar aquela cujo URL do app da Web é o endereço /exec que você
   usa. Anote o número da versão que aparece nela: ele serve para desfazer, se
   for preciso. Clique no lápis (Editar), escolha "Nova versão" no campo
   Versão e clique em Implantar. Não mude "Executar como" nem "Quem pode
   acessar".

6. Teste e, se precisar, desfaça.
   Feche as abas antigas do aplicativo e abra o mesmo endereço /exec numa aba
   nova. A base pode continuar como 2.10.2 e a programação como 2.11: esta
   correção não muda esses rótulos. Se o erro continuar, confira se você
   atualizou a implantação que tem esse mesmo endereço. Para desfazer:
   Implantar > Gerenciar implantações > a mesma implantação > lápis > no campo
   Versão, escolha a versão anotada no passo 5 > Implantar. O endereço não
   muda.

ATENÇÃO: QUANDO PARAR
- Não apague a planilha, não crie outro projeto, não reimporte faturas e não
  cole funções novas no Código.gs.
- Pare e não publique se: no passo 2, algum resultado mandar parar; a
  declaração não for encontrada; um acionador usar o nome sem o _; ou um dos
  verificadores dos passos 3 e 4 não der ok: true. Para o verificador
  opcional, leia antes o item 5 da seção dele: um item em "problemas" pode
  ser alarme falso.
- Se você já tinha digitado o _ quando precisou parar, desfaça com Ctrl+Z (no
  Mac, ⌘Z) até a linha voltar a ser o que era; se já tinha salvado, salve de
  novo.
- O que enviar está em "SE HOUVER OUTRO ERRO", no fim deste arquivo.

ALTERNATIVA — CORREÇÃO AUTOMÁTICA PELO HTML
Ela substitui só a EDIÇÃO do passo 2 (acrescentar o _ na declaração). A busca
do nome antigo nos arquivos que você não enviar e na página Acionadores
continua necessária.
Abra Corrigir_Conexao_Programacao_2_11_R4.html num navegador atual e clique
em "Correção automática" no índice do topo (a ferramenta abre sozinha).
- No campo "1. Código.gs", escolha a cópia do passo 1 (em UTF-8) ou cole o
  código.
- Opcional: no campo "2. Outros arquivos do projeto", escolha os outros
  arquivos .gs e .html, salvos em UTF-8 com o mesmo nome e a mesma terminação
  do editor (também serve Index.html.txt). Pode escolher vários de uma vez
  (Ctrl+clique; no Mac, ⌘+clique) ou um de cada vez: cada escolha soma à
  lista. Não inclua o Código.gs ali.
- Clique em "Diagnosticar e corrigir".
A página lê o código com o acorn (um leitor de JavaScript incluído nela), não
executa nada e não usa a rede. Nos arquivos enviados, ela confere: se a função
chamada com _ só existe sem o _, e se a declaração e a chamada estão nos
arquivos enviados; se o nome antigo aparece em mais algum ponto, inclusive
entre aspas (menus e acionadores), nos trechos <? ?> e nos .html
(comentários e mensagens de texto não contam); no servidor, nomes usados e
não encontrados; na tela, chamadas google.script.run e funções chamadas (ou
com nome terminado em _) que não estão nos .html enviados. Ela só gera código
quando a correção é segura nos arquivos enviados. Problemas fora desta
correção aparecem como aviso e não impedem a correção nem a publicação. Nomes
de bibliotecas ou de arquivos não enviados aparecem em "Para conferir".
Resultados possíveis:
- "Correção gerada": copie ou baixe o código COMPLETO, substitua todo o
  conteúdo do Código.gs (Ctrl+A e Ctrl+V; no Mac, ⌘A e ⌘V) e salve. Antes de
  publicar, procure p211Base_getInteressesSnapshot nos arquivos que você não
  enviou e na página Acionadores (como no passo 2). Depois siga os passos 3
  a 6. Não cole no final.
- "Nenhuma alteração necessária" ou "A correção desta conexão já está no
  código": não substitua nada. Se só o Código.gs foi enviado, faça a busca do
  passo 2 nos outros arquivos e nos Acionadores. Depois siga os passos 3 a 6.
  Problemas listados que não têm relação com esta correção não impedem
  publicar.
- "Nada foi gerado" ou "problemas prováveis ligados a esta correção": não
  publique; siga o próximo passo que a página mostra. Se não souber o que
  fazer, clique em "Copiar relatório" e envie o texto (só tem nomes de
  funções e números de linha).

VERIFICADOR DE INTEGRAÇÃO (OPCIONAL)
Uma conferência extra, feita dentro do Apps Script. Ele lê o texto das
funções do projeto e lista cada nome terminado em _ que é usado mas não existe,
além de sobras do nome antigo desta correção. Só faz leitura: não executa o
código do projeto, não abre a planilha, não grava dados e não cria
acionadores.
O que ele não lê: arquivos .html; chamadas google.script.run; o corpo de
funções criadas com const, let ou class (essas ele só consulta para saber se
existem); funções que só existem dentro de outra função ou de um módulo;
objetos criados com const, let ou Object.create; e código fora de funções,
como listas de menus guardadas em var.
Como instalar e usar:
1. No editor, clique em Arquivos > + > Script e dê o nome VerificadorIntegracao.
2. O arquivo novo vem com um exemplo (function myFunction() { }). Clique dentro
   dele e apague tudo: Ctrl+A e Delete (no Mac, ⌘A e Delete).
3. Cole o código do ANEXO (no fim deste arquivo) ou use o botão Copiar da
   seção "Verificador de integração" do HTML. Salve.
4. Com esse arquivo aberto, escolha verificarIntegracaoFinanceira na lista ao
   lado de Executar e clique em Executar. Se o nome não aparecer na lista, o
   código foi colado dentro do exemplo: apague tudo e cole de novo.
5. Leia o Registro de execução:
   - INTEGRACAO_FINANCEIRO ok: true quer dizer que não há itens em
     "problemas" nas partes que ele lê. Leia também os avisos;
   - "problemas": provável erro real, mas pode ser alarme falso quando o nome
     é criado dentro de outra função ou de um módulo. Antes de deixar de
     publicar, procure o nome com Ctrl+F (no Mac, ⌘F) em todos os arquivos
     .gs: se ele estiver declarado (com function, const, let ou dentro do
     mesmo módulo), não altere nada e envie a saída. Se não estiver, siga a
     sugestão do item. Se ela disser "Não renomeie", não altere nada e envie
     a saída;
   - se você mudar o código por causa de uma sugestão, salve, repita os passos
     3 e 4 e rode o verificador de novo antes de publicar;
   - "avisos": podem não ser erro (por exemplo, um nome usado só depois de um
     teste typeof, ou um nome interno de um módulo). Leia cada um; sozinhos
     eles não impedem a publicação;
   - se funcoesAnalisadas for 0, ou muito menor que o número de funções do seu
     projeto, o resultado não vale como aprovação. Confira se o arquivo foi
     criado no projeto certo;
   - se ele não conseguir terminar, escreve uma linha dizendo isso. Não indica
     erro no aplicativo e, sozinho, não impede a publicação: valem os
     verificadores dos passos 3 e 4.
6. APAGUE o arquivo VerificadorIntegracao antes de publicar (passo 5 da
   correção manual): menu de três pontos ao lado do nome > Excluir. A função
   dele tem nome público e, se o arquivo ficar, vai junto na versão
   publicada.

O QUE ESTA REVISÃO CORRIGE
Uma auditoria com revisores independentes conferiu a R1 (o guia anterior), a
R2 e a R3. Cada problema foi reproduzido antes de entrar na lista: 27 na R1 e
69 na R2. Na R3, 37 desses pontos tinham ficado incompletos e havia 33
problemas novos. A R4 trata esses 70 pontos. O que só pode ser confirmado no
Apps Script real está descrito em "ESCOPO E LIMITES" e nos limites do
verificador. Principais mudanças:
- Segurança da correção: a ferramenta confere o nome antigo também nos
  trechos <? ?> que ficam dentro de comentários (o servidor os executa) e,
  com a declaração já corrigida, faz a mesma busca completa que faz antes da
  correção. Ela só diz que o nome está correto quando acha a declaração com _.
- Menos alarmes falsos: mensagens de texto, blocos <script> desativados,
  window.nome = ... e trechos <?!= ... ; ?> não geram mais bloqueio nem
  problema. Avisos de "nome antigo" valem só para esta correção.
- Resultado coerente: com o código já corrigido, problemas sem relação com
  esta correção não mandam mais "não publicar". O quadro final lembra de
  procurar o nome nos arquivos não enviados e na página Acionadores.
- Funcionamento: linhas do relatório contadas como no editor, inclusive
  dentro de textos longos; páginas com muitos blocos <script> lidas em poucos
  segundos; outros arquivos somados a cada escolha, com remoção um por um; um
  arquivo recusado não descarta os outros.
- Passo a passo: o passo 2 manda procurar em todos os arquivos e nos
  Acionadores antes de digitar o sublinhado, explica como desfazer e como
  tratar sobras do nome antigo; o passo 3 manda voltar ao Editor; quem já usou
  a R2 é lembrado de apagar o VerificadorIntegracao.
- Verificador opcional: não executa getters, não se conta, lê objetos dentro
  de objetos e valores padrão, entende módulos, typeof(nome), rótulos e campos
  de classe; o guia explica como reconhecer um alarme falso.
- Acessibilidade e leitura (HTML): foco do teclado mantido no resultado, o _
  destacado visível no celular, nomes que só quebram em pontos seguros.

Pontos da auditoria da R3 (70), tratados nesta versão:
1. Quem usava a correção automática era orientado a pular o passo 2, e o
   quadro final não pedia a busca do nome nos arquivos não enviados e na
   página Acionadores.
2. Nos trechos <? ?> e no <script> das telas, uma função ausente passada sem
   parênteses (como callback) não era apontada.
3. Um trecho <? ?> dentro de um comentário // ou /* */ do <script> era
   ignorado, embora o servidor o execute; e um trecho com ponto e vírgula no
   fim desligava a conferência dos outros trechos do arquivo.
4. Uma tela que reaproveita google.script.run (função que devolve a cadeia,
   seta, const { run } = google.script ou variável de outro <script>) ficava
   sem conferência.
5. Com a R1 já aplicada, um menu ou acionador com o nome antigo entre aspas
   recebia a caixa verde.
6. Na tela, uma função que só existe no servidor usada como callback ou num
   onclick não era apontada, e uma página podia usar função de outra página
   que ela não inclui.
7. Quando só o Código.gs era enviado, a mensagem de sucesso não pedia a busca
   nos outros arquivos e na página Acionadores.
8. Depois da correção manual, globalThis.nome(...), this.nome(...) e typeof
   nome com o nome antigo passavam sem aviso.
9. O nome antigo numa mensagem de texto (console.log, Logger.log, throw new
   Error) ainda bloqueava a correção, com um motivo falso.
10. Um <script> desativado dentro de <!-- --> ainda era lido como código
    ativo.
11. Dois blocos <script> da mesma página com o mesmo const não eram apontados,
    e uma função de um .html não enviado era dada como “só do servidor”.
12. Uma cópia de segurança do Código.gs com outro nome e conteúdo um pouco
    diferente gerava problemas falsos.
13. A página prometia conferir mais do que conferia (nomes sem parênteses no
    servidor e funções da tela).
14. O verificador opcional parava com erro quando alguma função tinha o texto
    “constructor”, “__proto__” ou “toString”.
15. Com a chamada com _ num arquivo não enviado, a página dizia que o nome
    estava correto.
16. Os títulos das listas não acompanhavam o resultado (“não impedem a
    correção” quando nada foi gerado).
17. A falha interna da conferência final aparecia sem próximo passo, e o
    quadro “Atenção” não citava o relatório.
18. Em navegadores um pouco antigos, escolher um arquivo falhava sem mensagem
    e a página analisava o código anterior.
19. Um arquivo salvo com quebras de linha do Windows era medido com um
    caractere a mais por linha.
20. Perto do limite, o mesmo código era recusado como arquivo e aceito quando
    colado.
21. Clicar em “Diagnosticar e corrigir” enquanto o arquivo ainda era lido
    usava o texto anterior.
22. Um segundo clique durante a análise ainda repetia tudo.
23. Alguns bloqueios ainda não diziam o próximo passo nem a quem enviar o
    relatório.
24. O verificador opcional não lia objetos dentro de objetos e reprovava
    módulos e variáveis let sem valor.
25. A nova conferência de outros usos derrubava o verificador opcional com
    textos como “constructor”.
26. O guia mandava parar diante de qualquer problema do verificador opcional,
    sem dizer que pode ser alarme falso.
27. O verificador opcional não reconhecia typeof com parênteses, como
    typeof(nome_).
28. Quem instalou o VerificadorIntegracao pela R2 não era lembrado de apagá-lo

30. No TXT, três cliques no nome copiavam também a quebra de linha, e a busca

31. Depois da correção manual, um menu ou acionador com o nome antigo entre
    aspas ainda recebia confirmação falsa.
32. Ainda restava a frase técnica “Não mexa nos parâmetros nem no corpo da
    função”.
33. O guia não avisava que um problema do verificador opcional pode ser alarme
    falso, e a frase sobre os testes prometia mais do que eles mostravam.
34. No celular, o quadro “Deve ficar assim” escondia o _ destacado e tinha uma
    faixa vazia; o contorno do destaque tinha pouco contraste.
35. A 320 px, os nomes do passo 2 ainda se partiam logo antes do “_(”, e os

39. Com a correção da R1 ou da R2 já aplicada, a ferramenta dizia “Nenhuma

ESCOPO E LIMITES
- O Código.gs real não foi visto. A ferramenta foi testada com 87 casos
  fictícios (baseados nos problemas apontados pela auditoria, mais arquivos de
  até 6 milhões de caracteres), a página com 55 conferências num
  navegador Chromium e o verificador com 37 casos. O verificador foi
  testado num ambiente que imita o Apps Script (Node.js), não no próprio Apps
  Script.
- A ferramenta confere só os arquivos enviados. Nomes usados em arquivos não
  enviados, menus e acionadores criados fora do código não são vistos. Por
  isso o passo 2 pede a busca em todos os arquivos e na página Acionadores.
- Os itens "para conferir" podem ser alarmes falsos. Os "problemas prováveis"
  da ferramenta e os "problemas" do verificador opcional têm mais chance de
  ser erros reais, mas também devem ser confirmados.
- Esta correção não resolve um ReadTimeout (tempo esgotado) independente nem
  valida a leitura (OCR) real das faturas. Se o ReadTimeout voltar, os pontos
  a revisar no Código.gs são: leitura em bloco com getValues(), cache do mês
  com CacheService e LockService nas gravações. Isso só pode ser confirmado
  com o código completo.

          else return;
          var d = 0;
          for (; x < t.length; x++) {
            var tk = t[x];
            if (abre(tk)) d++;
            else if (fecha(tk)) { d--; if (d < 0) return; }
            else if (d === 0 && tk.t === 'p' && tk.v === ';') return;
            else if (d === 0 && tk.t === 'p' && tk.v === ',') { x++; break; }
            else if (d === 0 && tk.nl && x > k + 1 && (tk.t === 'id' || tk.t === 'num' || tk.t === 'str') && !(t[x - 1].t === 'p' && t[x - 1].v !== ')' && t[x - 1].v !== ']' && t[x - 1].v !== '}')) return;
          }
          if (x >= t.length) return;
        }
      }
      /* Campos de classe (total_ = 0; #cache_ = 1): ficam no nível de cima do corpo da classe. */
      var noCorpoDaClasse = [], pilha = [], classePendente = -1;
      for (var y = 0; y < t.length; y++) {
        var ty = t[y];
        noCorpoDaClasse[y] = pilha.length > 0 && pilha[pilha.length - 1] === 'classe';
        if (ty.t === 'id' && !ty.ponto && ty.v === 'class' && !eh(y + 1, ':')) { classePendente = 0; continue; }
        if (classePendente === 0 && ty.t === 'p' && /^(:|,|;|=|\)|\]|\}|\}\$)$/.test(ty.v)) classePendente = -1;
        if (abre(ty)) {
          if (classePendente === 0 && ty.v === '{') { pilha.push('classe'); classePendente = -1; }
          else { pilha.push('outro'); if (classePendente >= 0) classePendente++; }
          continue;
        }
        if (fecha(ty)) { pilha.pop(); if (classePendente > 0) classePendente--; }
      }
      for (var k = 0; k < t.length; k++) {
        var tk = t[k];
        if (tk.t !== 'id' || tk.ponto) continue;
        if (tk.v === 'function') {
          var x = k + 1; if (eh(x, '*')) x++;
          if (t[x] && t[x].t === 'id') { locais[t[x].v] = true; x++; }
          if (eh(x, '(')) { var f = par(x, '(', ')', 1); if (f > 0) nomesDoPadrao(x, f); }
          continue;
        }
        if (tk.v === 'class' && t[k + 1] && t[k + 1].t === 'id' && !PALAVRAS[t[k + 1].v]) { locais[t[k + 1].v] = true; continue; }
        if (tk.v === 'catch' && eh(k + 1, '(')) { var fc = par(k + 1, '(', ')', 1); if (fc > 0) nomesDoPadrao(k + 1, fc); continue; }
        if (tk.v === 'var' || tk.v === 'let' || tk.v === 'const') { declaracao(k); continue; }
      }
      for (var m = 0; m < t.length; m++) {
        if (!eh(m, '=>')) continue;
        if (eh(m - 1, ')')) { var ab = par(m - 1, ')', '(', -1); if (ab >= 0) nomesDoPadrao(ab, m - 1); }
        else if (t[m - 1] && t[m - 1].t === 'id') locais[t[m - 1].v] = true;
      }
      for (var q = 0; q < t.length; q++) {
        var tq = t[q];
        if (tq.t !== 'id' || tq.ponto || PALAVRAS[tq.v]) continue;
        var ant = t[q - 1];
        if (ant && ant.t === 'id' && (ant.v === 'function' || ant.v === 'class' || ant.v === 'break' || ant.v === 'continue')) continue;
        if (eh(q - 1, '#')) continue;
        if (eh(q + 1, ':') && (eh(q - 1, '{') || eh(q - 1, ','))) continue;
        /* Rótulo de laço (saida_: for ...). */
        if (eh(q + 1, ':') && (eh(q - 1, ';') || eh(q - 1, '}'))) continue;
        if (noCorpoDaClasse[q] && !eh(q + 1, '(') && (eh(q + 1, '=') || eh(q + 1, ';') || eh(q + 1, '}') || idEm(q - 1, 'static'))) continue;
        if (eh(q + 1, '(')) {
          var fp = par(q + 1, '(', ')', 1);
          var antOk = !ant || eh(q - 1, '{') || eh(q - 1, ',') || eh(q - 1, '}') || eh(q - 1, ';') || eh(q - 1, '*') || (ant.t === 'id' && /^(get|set|static|async)$/.test(ant.v));
          if (fp > 0 && eh(fp + 1, '{') && antOk) { nomesDoPadrao(q + 1, fp); continue; }
        }
        /* typeof nome, typeof (nome): teste de existência. typeof nome(...) é chamada. */
        var testado = (idEm(q - 1, 'typeof') && !eh(q + 1, '(')) || (eh(q - 1, '(') && idEm(q - 2, 'typeof') && eh(q + 1, ')'));
        if (testado) { guardados[tq.v] = true; continue; }
        refs[tq.v] = true;
        if (/_$/.test(tq.v)) usos.push(tq.v);
      }
      return { locais: locais, usos: usos, refs: refs, guardados: guardados, textos: r.textos };
    }

    /* Lista as funções do projeto sem executar nada: lê os descritores, não os valores (getters não rodam). */
    var nomes = [];
    try { nomes = Object.getOwnPropertyNames(g); } catch (e) { nomes = []; }
    var fontes = novo(), vistos = [];
    function fonteDe(f) { try { var s = Function.prototype.toString.call(f); return NATIVO.test(s) ? null : s; } catch (e) { return null; } }
    function descritor(o, k) { try { return Object.getOwnPropertyDescriptor(o, k) || null; } catch (e) { return null; } }
    function objetoSimples(v) {
      if (!v || typeof v !== 'object' || Array.isArray(v)) return false;
      var p; try { p = Object.getPrototypeOf(v); } catch (e) { return false; }
      return p === Object.prototype || p === null;
    }
    function guardar(nome, f, deObjeto) { var s = fonteDe(f); if (s) fontes[nome] = { src: s, deObjeto: deObjeto }; }
    function lerAcessores(nome, d) { if (d.get) guardar(nome + ' (get)', d.get, true); if (d.set) guardar(nome + ' (set)', d.set, true); }
    function lerObjeto(prefixo, v, nivel) {
      if (nivel > 4 || vistos.indexOf(v) >= 0) return;
      vistos.push(v);
      var chaves; try { chaves = Object.getOwnPropertyNames(v); } catch (e) { return; }
      chaves.forEach(function (c) {
        var d = descritor(v, c), nome = prefixo + '.' + c;
        if (!d) return;
        lerAcessores(nome, d);
        if (!('value' in d)) return;
        if (typeof d.value === 'function') guardar(nome, d.value, true);
        else if (objetoSimples(d.value)) lerObjeto(nome, d.value, nivel + 1);
      });
    }
    nomes.forEach(function (n) {
      if (n === PROPRIA) return;
      var d = descritor(g, n);
      if (!d) return;
      lerAcessores(n, d);
      if (!('value' in d)) return;
      if (typeof d.value === 'function') guardar(n, d.value, false);
      else if (objetoSimples(d.value)) lerObjeto(n, d.value, 1);
    });
    var evalFunciona = false;
    try { evalFunciona = (0, eval)('1') === 1; } catch (e) { evalFunciona = false; }
    /* Nome existe no escopo global? Lê o nome sem chamar nada; let sem valor também conta. */
    function existe(nome) {
      if (temProp(fontes, nome) && !fontes[nome].deObjeto) return true;
      try { if (nome in g) return true; } catch (e) { /* segue */ }
      if (!evalFunciona) return null;
      try { (0, eval)(nome); return true; } catch (e) { return (e instanceof ReferenceError) ? false : null; }
    }
    function ehDoProjeto(nome) { return temProp(fontes, nome) && !fontes[nome].deObjeto; }

    var analisadas = 0, usosPorNome = novo(), refsPorNome = novo(), testesPorNome = novo(), textosPorValor = novo(), abreviados = novo(), avisos = [], problemas = [];
    function anotar(mapa, nome, fn) { var l = mapa[nome] || (mapa[nome] = []); if (l.indexOf(fn) < 0) l.push(fn); }
    var RE_ABREVIADO = new RegExp('[{,]\\s*' + ALVO + '\\s*[,}]');
    Object.keys(fontes).forEach(function (fn) {
      var a, info = fontes[fn];
      try { a = analisarFonte(info.src); } catch (e) { avisos.push({ nome: fn, motivo: 'O código desta função não pôde ser lido.' }); return; }
      analisadas++;
      a.usos.forEach(function (u) {
        if (a.locais[u]) return;
        var e = usosPorNome[u] || (usosPorNome[u] = { em: [], semTeste: [], soEmObjetos: true });
        if (e.em.indexOf(fn) < 0) e.em.push(fn);
        if (!a.guardados[u] && e.semTeste.indexOf(fn) < 0) e.semTeste.push(fn);
        if (!info.deObjeto) e.soEmObjetos = false;
      });
      Object.keys(a.refs).forEach(function (n) { if (!a.locais[n]) anotar(refsPorNome, n, fn); });
      Object.keys(a.guardados).forEach(function (n) { if (!a.locais[n]) anotar(testesPorNome, n, fn); });
      a.textos.forEach(function (s) { if (/^[\p{ID_Start}$_][\p{ID_Continue}$]*$/u.test(s)) anotar(textosPorValor, s, fn); });
      if (RE_ABREVIADO.test(info.src)) abreviados[fn] = true;
    });

    Object.keys(usosPorNome).sort().forEach(function (nome) {
      var info = usosPorNome[nome], ex = existe(nome);
      if (ex === true) return;
      var item = { nome: nome, usadoEm: info.em };
      var base = nome.replace(/_+$/, ''), dica = '';
      if (base && ehDoProjeto(base)) {
        var outros = (refsPorNome[base] || []).concat((testesPorNome[base] || []).map(function (f) { return f + ' (typeof)'; })).concat((textosPorValor[base] || []).map(function (f) { return f + ' (entre aspas)'; }));
        dica = outros.length
          ? 'Existe "' + base + '" sem o _, mas esse nome também é usado em: ' + outros.join(', ') + '. Não renomeie; envie esta saída.'
          : 'Existe "' + base + '" sem o _. Procure "' + base + '" com Ctrl+F (no Mac, ⌘F) em todos os arquivos .gs e .html e veja a página Acionadores. Se ele só aparecer na própria declaração, acrescente o _ nela.';
      }
      if (ex === null) { item.motivo = 'Não foi possível confirmar se este nome existe. Confira com Ctrl+F.' + (dica ? ' ' + dica : ''); avisos.push(item); return; }
      if (!info.semTeste.length) { item.motivo = 'Só é usado em funções que também testam "typeof ' + nome + '". Se o uso só acontece quando a função existe, não é erro.' + (dica ? ' ' + dica : ''); avisos.push(item); return; }
      if (!dica && info.soEmObjetos) { item.motivo = 'Só aparece em funções guardadas dentro de objetos. Pode ser um nome interno do próprio módulo (criado dentro dele), que o verificador não enxerga. Confira com Ctrl+F antes de alterar qualquer coisa.'; avisos.push(item); return; }
      item.usadoEm = info.semTeste;
      item.sugestao = dica || 'Nenhuma função com esse nome foi encontrada.';
      problemas.push(item);
    });

    /* Sobras do nome antigo desta correção, depois que a função ganhou o _. */
    if (ehDoProjeto(ALVO + '_') && existe(ALVO) === false) {
      var usosAntigos = (refsPorNome[ALVO] || []).concat((testesPorNome[ALVO] || []).filter(function (f) { return (refsPorNome[ALVO] || []).indexOf(f) < 0; }).map(function (f) { return f + ' (typeof)'; }));
      var textosAntigos = textosPorValor[ALVO] || [];
      var abreviado = usosAntigos.some(function (f) { return abreviados[f.replace(/ \(typeof\)$/, '')]; });
      if (usosAntigos.length) problemas.push({ nome: ALVO, usadoEm: usosAntigos, sugestao: 'A função se chama "' + ALVO + '_", mas estes pontos ainda usam o nome antigo, sem o _. Nesses arquivos .gs, acrescente o _ também neles (é a mesma correção de um caractere).' + (abreviado ? ' Se o nome estiver sozinho entre chaves, como { ' + ALVO + ' }, escreva ' + ALVO + ': ' + ALVO + '_ para não mudar o nome da chave.' : '') + ' Depois salve e repita os passos 3 e 4.' });
      if (textosAntigos.length) problemas.push({ nome: ALVO, usadoEm: textosAntigos.map(function (f) { return f + ' (entre aspas)'; }), sugestao: 'O nome antigo aparece sozinho entre aspas. Se for um item de menu, um acionador ou uma rota, ele deixou de funcionar quando a função ganhou o _. Não altere; envie esta saída.' });
    }

    if (!evalFunciona) avisos.push({ nome: '-', motivo: 'O verificador não conseguiu testar nomes criados com let, const ou class. Os itens acima podem estar incompletos.' });
    if (!analisadas) avisos.push({ nome: '-', motivo: 'Nenhuma função do projeto foi listada. Confira se este arquivo foi criado no projeto certo.' });
    var ok = analisadas > 0 && problemas.length === 0;
    var resultado = {
      tipo: 'INTEGRACAO_FINANCEIRO', ok: ok, funcoesAnalisadas: analisadas, problemas: problemas, avisos: avisos,
      limites: 'Lê funções declaradas com function e funções guardadas em objetos criados com var (até 4 níveis), inclusive get e set. Não lê arquivos .html, chamadas google.script.run, o corpo de funções criadas com const, let ou class, funções que só existem dentro de outra função ou de um módulo, objetos criados com const, let ou Object.create, nem código fora de funções.'
    };
    console.log('INTEGRACAO_FINANCEIRO ok: ' + ok + ' · funções analisadas: ' + analisadas + ' · problemas: ' + problemas.length + ' · avisos: ' + avisos.length);
    console.log(JSON.stringify(resultado));
    return resultado;
  }
